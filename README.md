# SNAP Store — версія 1

Магазин чоловічого одягу, взуття й аксесуарів. Українська та англійська, гривні, світла й темна теми, власний дизайн у графітових, срібних і синіх кольорах. За основу структури взято наданий приклад ANSWEAR; код і графіка вітрини створені для SNAP.

**Стан передачі:** реалізована версія з базою даних і конфігурацією Railway. Продажі та індексація початково вимкнені. Оновлення 20.09.2026 пройшло 33 автоматичні тести й браузерну перевірку основних сторінок на мобільній, планшетній і настільній ширині. Для входу потрібен налаштований відправник Resend або SMTP; зовнішня доставка листів і приймання на фізичних телефонах ще не підтверджені. Деталі — `docs/QA.md`.

## Що є

- Головна, категорії, 100 демо-карток: по 10 для Alexander McQueen, Balenciaga, Dior, Fendi, Givenchy, Gucci, Hermès, Valentino, Louis Vuitton, Prada.
- Фільтри за категорією, брендом, ціною, кольором, розміром і сезоном; сортування, пошук із підказками, обране, нещодавно переглянуті товари.
- Картка товару, фото, вибір кольору та розміру, таблиця наявності, швидке додавання, бічний кошик.
- Оформлення по Україні: Нова пошта, Укрпошта або кур’єр. Адресу чи відділення покупець вводить вручну. Оплата при отриманні. Інтеграції API перевізників і автоматичного створення ТТН немає; номер відправлення додає адміністратор.
- Одноразовий код на email, автоматичне створення кабінету після підтвердження адреси, історія покупок, збережені адреси, запит повернення.
- Знижки, промокоди, бонусний рахунок, відгуки після підтвердженої покупки.
- SNAP Studio: три запитання, до трьох образів із доступних товарів у межах бюджету, обертальна 3D-візуалізація силуету та кольорів. Без ключа AI використовується прозоро позначений підбір за правилами. 3D не є точною моделлю товару чи віртуальною приміркою.
- Адмінка `/admin`: товари, завантаження фотографій, ціни, кольори/розміри/наявність, замовлення й ТТН, промокоди, покупці, підписки, листи, тексти та налаштування. Зміни записуються в базу; дії адміністратора — у журнал.
- Підписка на новини та GA4 / Meta Pixel / TikTok Pixel підготовлені, початково вимкнені. Розсилання маркетингових кампаній не реалізоване. Аналітика завантажується лише після згоди відвідувача у відкритому магазині; доступне відкликання згоди.
- Серверні метадані, canonical, robots.txt, sitemap.xml, Product/Offer для реальних товарів.

Фотографії демо-карток — шість створених для макета зображень без логотипів. Вони повторюються між картками й не є фотографіями реального асортименту. Назви, ціни, склад і таблиці розмірів також демонстраційні. Магазин прямо зазначає, що продає репліки, не оригінали.

## Правила розрахунку

Усі суми на сервері зберігаються цілими копійками. Інтерфейс показує гривні.

| Умова | Результат |
| --- | --- |
| 1–4 одиниці в кошику | Без знижки за кількість |
| 5 одиниць | 5% |
| 6–19 одиниць | Кількість одиниць = відсоток знижки |
| 20 і більше | 20% |
| Є промокод | Застосовується більша знижка: промокод або кількість |
| Списання бонусів | Після знижки, до 10% суми та в межах балансу |
| Нарахування бонусів | 3% сплачуваної суми товарів після статусу «Отримано» |
| Повернення / скасування | Списані бонуси повертаються, нараховані за повернення відкликаються |
| Доставка від 7777 грн | За рахунок магазину, поріг після знижок і бонусів |

Комісія за післяплату не входить у безкоштовну доставку. Відсотки бонусів та поріг доставки змінюються в адмінці. Демо-замовлення не нараховують і не списують справжні бонуси та не створюють підтверджених відгуків.

## Запуск на комп’ютері

Потрібен **Node.js 24**. Виконувати команди з папки `snap-store`.

```bash
npm ci
npm run dev
```

Відкрити `http://localhost:4173`. Дані зберігаються в `.data/snap.sqlite`, фото — `.data/uploads`.

Для локальної перевірки входу й адмінки **без справжньої пошти**:

```bash
DEV_AUTH=true ADMIN_EMAILS=admin@snap.test npm run dev
```

Увійти з `admin@snap.test`; тестовий код буде показаний у формі лише в цьому локальному режимі. У `NODE_ENV=production` цей режим примусово вимкнений, незалежно від значення `DEV_AUTH`.

Файл `.env.example` — шаблон змінних, а не активна конфігурація. Node не підхоплює `.env` автоматично. Для власного локального файлу використовуйте `node --env-file=.env server/index.js`; для Railway додайте змінні у Variables.

```bash
npm test       # автоматично збирає клієнт, потім запускає всі тести
npm run check # синтаксис сервера
npm audit     # актуальні відомі вразливості залежностей
```

## Railway: порядок розгортання

1. Завантажити вміст папки `snap-store` у власний приватний GitHub-репозиторій. Не завантажувати `.env`, `.data`, `node_modules` чи базу з особистими даними. Можна також завантажити цей проєкт через авторизований Railway CLI.
2. Створити Railway service з репозиторію. Якщо папка проєкту вкладена, вказати її як Root Directory. Railway використовує включений `Dockerfile` і `railway.toml`.
3. **Перед першим запуском приєднати Volume до сервісу з Mount Path `/data`.** SQLite й фотографії мають залишатися на цьому томі після перевипуску контейнера.
4. Залишити **одну репліку** застосунку. Ця версія використовує локальну SQLite; для горизонтального масштабування потрібне перенесення на спільну БД і файлове сховище.
5. У Variables додати значення з таблиці нижче. Створити публічний HTTPS-домен і встановити його як `APP_URL`, без кінцевого шляху.
6. Запустити deployment, перевірити `/api/health`: відповідь `{"status":"ok"}`. Перезапустити сервіс і перевірити, що редагування картки та завантажене фото збереглися.
7. Увійти в `/admin` через дозволений email, заповнити справжні товари, контакти, реквізити й умови. Перевірити отримання коду на вашому домені.
8. Після перевірки відкрити продажі в адмінці. Здійснити контрольне замовлення, перевірити листи покупцеві та продавцю, доставку, бонуси й повернення. Лише після приймання вмикати індексацію та рекламу.

| Змінна | Значення / призначення |
| --- | --- |
| `NODE_ENV` | `production` |
| `APP_URL` | Ваш HTTPS origin, наприклад `https://shop.example.com` |
| `DATA_DIR` | `/data`, точно як Mount Path |
| `RAILWAY_RUN_UID` | `0` для доступу до root-owned Volume; entrypoint виправляє власника папки та запускає Node від непривілейованого користувача `node` |
| `SESSION_SECRET` | Випадковий секрет щонайменше 32 символи; не змінювати при кожному deployment |
| `ADMIN_EMAILS` | Додаткові email адміністраторів через кому. Власник `danilolisnicuk9@gmail.com` також явно заданий у `server/config.js` |
| `MAIL_PROVIDER` | `resend` для HTTPS або `smtp`; порожнє значення вибирає Resend, якщо є його ключ |
| `RESEND_API_KEY` | Ключ Resend із правом відправлення для підтвердженого домену |
| `SMTP_HOST`, `SMTP_PORT` | Сервер і порт поштового провайдера, зазвичай 587 або 465 |
| `SMTP_SECURE` | `true` для 465; `false` для 587 з STARTTLS |
| `SMTP_USER`, `SMTP_PASS` | Облікові дані SMTP у Variables, не в коді |
| `MAIL_FROM` | Підтверджений відправник, наприклад `SNAP <shop@example.com>` |
| `MAIL_REPLY_TO` | Адреса для відповідей покупців; можна вказати email власника, якщо домен відправника не приймає листи |
| `ORDER_EMAIL` | `danilolisnicuk9@gmail.com` або інша адреса продавця для замовлень |
| `DEV_AUTH` | `false` |
| `PORT` | Railway надає або можна встановити 3000 |

Створити випадковий секрет локально:

```bash
node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"
```

Секрети вводьте безпосередньо в Railway Variables. Не надсилайте SMTP-паролі, одноразові коди чи API-ключі в чат.

Railway монтує Volume лише під час старту контейнера; права і база ініціалізуються entrypoint/сервером саме тоді. Документація: [Railway Volumes](https://docs.railway.com/volumes).

### Вхід і поштовий сервіс

На Railway Free, Trial та Hobby вихідний SMTP заблокований; використовуйте HTTPS API Resend. SMTP підходить для Pro та вищих планів. Джерело: [Railway Outbound Networking](https://docs.railway.com/networking/outbound-networking).

Для Resend додайте у Variables `MAIL_PROVIDER=resend`, `RESEND_API_KEY` та `MAIL_FROM=SNAP <shop@ваш-підтверджений-домен>`. Домен відправника потрібно підтвердити в Resend через DNS. Gmail-адреса власника підходить для входу та отримання замовлень, але не стає підтвердженим доменом відправника Resend. Тестовий відправник `onboarding@resend.dev` призначений для обмеженого тестування; його не слід використовувати для входу покупців. Документація: [Resend Send Email](https://resend.com/docs/api-reference/emails/send-email).

Код входу діє 10 хвилин, споживається один раз і має ліміт спроб. Повторне надсилання доступне через 60 секунд. Адмінський email не обходить підтвердження. Роль власника задана в `server/config.js` за явним запитом власника цього магазину; її можна змінити там, а додаткових адміністраторів — через `ADMIN_EMAILS`. Не копіюйте цю конфігурацію в незалежний магазин іншого власника.

Оновлення від 20.09.2026 використовує нові надані PNG логотипа, знака й перевізників без обрізання та перефарбовування. Знак використовується як favicon і apple-touch-icon. Лічильники мають спільне вирівнювання, формат `99+`, порожній кошик не показує нульову позначку.

## Наповнення через адмінку

Відкрийте «Товари», знайдіть бренд і картку, замініть UA/EN назви та описи, ціни, фото, фактичні заміри. Перевірте кожну комбінацію кольору й розміру. Порядок фото визначає головне зображення. Зніміть «Демо» лише для реального асортименту; сервер не дозволить опублікувати реальний товар із вбудованими демо-фото. Непотрібні картки деактивуйте.

У «Налаштуваннях» змініть тексти головної, виберіть товар для банера, додайте контакти, доставку, повернення, оферту й конфіденційність. Затвердження політик виконує власник. Початкові тексти — редакційні підказки для заповнення. Вони не видаються за готові документи продавця.

Перемикач «Продажі» блокується, поки немає поштового сервісу (Resend або SMTP), адреси замовлень, реквізитів, контактного email, затвердження політик і хоча б одного реального товару. Після увімкнення демо-картки автоматично зникають з каталогу, а їх оформлення забороняється.

Нові замовлення не відправляють товари автоматично. Адміністратор підтверджує їх, оформлює відправлення у перевізника, додає ТТН та змінює статус. «Отримано» слід виставляти лише після фактичного отримання: це нараховує бонуси та відкриває відгук. Повторне збереження статусу не дублює бонусні операції.

## AI та аналітика

Для зовнішнього AI-підбору додайте `AI_API_KEY`, `AI_API_URL` і `AI_MODEL`. Реалізований адаптер Chat Completions із `response_format: json_object`; провайдер і модель мають його підтримувати. Підтримуваний протокол: [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create). Адреса API задається власником, ключ залишається на сервері.

У запит передаються три відповіді й каталог (назви, ціни, типи, кольори), без email чи адрес покупців. Відповідь перевіряється: лише існуючі доступні товари, повний комплект, бюджет, різні образи. При помилці або тайм-ауті працює підбір за правилами з відповідним позначенням. 3D-силует малює Three.js у браузері; генерація точних 3D-моделей одягу не реалізована.

Аналітика налаштовується ID в адмінці. У першій версії події `purchase` означають **прийняте замовлення з післяплатою**, а не підтверджену оплату. Для виручки від доставлених замовлень потрібна окрема серверна інтеграція. Перевірте теги в кабінетах провайдерів на власному домені перед рекламою. Без ID та згоди клієнта вони не завантажуються.

## Дані, резервні копії та оновлення

`/data` містить `snap.sqlite`, файли WAL/SHM і `uploads/`. Не копіюйте один живий файл SQLite без узгодженого snapshot. Для офлайн-резервної копії зупиніть застосунок і скопіюйте **весь** `/data`; відновлюйте також при зупиненому застосунку. Налаштуйте автоматичні резервні копії Volume в Railway і перевірте відновлення у тестовому сервісі. Секрети Variables зберігайте окремо.

Перед оновленням: резервна копія, `npm ci`, `npm test`, потім deployment. Початковий seed виконується один раз і не перезаписує редагування в існуючій базі. Перевипуск коду не замінює товари: використовуйте адмінку. Зміна `SESSION_SECRET` анулює старі сесії та коди входу.

```text

server/index.js      API, auth, перевірки, листи, SEO, запуск

public/             Логотип, favicon, демо-зображення

```

Для приймання власником використовуйте `docs/QA.md`. Реального домену чи підключеного Railway-акаунта до комплекту не додано.

### Фото за кольором та бренди

У панелі керування → «Бренди» можна додати бренд, перейменувати його разом із товарами або видалити порожній бренд. У редакторі товару бренд вибирається зі списку. Під час першого запуску цієї версії міграція 2 переносить наявні бренди в окрему таблицю SQLite, не змінюючи товари чи замовлення.

У «Фото товару» виберіть спільну галерею або колір. Для кожної галереї доступно до 8 фото: завантаження кількох файлів, Ctrl+V / ⌘V, кнопка «Вставити з буфера» або HTTPS-посилання. Доступ до буфера залежить від дозволів браузера; вставлення клавішами й завантаження файлу залишаються доступними альтернативами. Перше фото кольору автоматично стає обкладинкою, якщо спільних фото ще немає. Кольори спочатку додаються нижче, в «Кольори та розміри».

Фото зберігаються у `colors[].images`; старі товари використовують `images` як запасну галерею. Вибір кольору змінює галерею на сторінці товару, фото швидкого перегляду, кошика та оформлення. У замовленні зберігається фото обраного кольору на момент покупки.

Редактор товару закривається лише хрестиком: клік на тло, Escape та збереження не закривають його. Після редагування фото або кольорів натисніть «Зберегти товар».

### Ціни за розмірами

У товарі → «Розміри та ціни» позначте S, M, L, XL, XXL і впишіть ціни в гривнях. Для взуття показуються числові розміри; інший розмір можна додати вручну. Порожня ціна використовує базову ціну товару. Наявність кожного поєднання кольору та розміру керується окремо нижче. Збережіть товар після змін.

Ціни зберігаються в `sizePrices` у копійках. Старі товари зберігають базову ціну. Каталог показує «від» для різних цін; вибір розміру оновлює ціну товару. Сервер рахує кошик, знижки, доставку та бонуси за ціною вибраного розміру, незалежно від переданих клієнтом сум. Уже створені замовлення зберігають початкові ціни.
